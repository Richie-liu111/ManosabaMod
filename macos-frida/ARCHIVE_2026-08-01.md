## 一、本次会话的核心结论 (推翻旧归档的 EEE 结论)

### 1. EEE 真因修正: 不是 LRP.ctor, 是 FSG AddConverter ⭐
旧归档把 EEE 归到 `LocalResourceProvider.ctor` — **错误**。探针证据:
- macOS 上 `LRP.ctor` 的 methodPointer / invoker **均非空**,`il2cpp_runtime_invoke` 直接成功。游戏自己也构造了两次(本地化 `Localization/Text` + `%DATA%/Resources`)。
- 真正的 EEE 是:
  ```
  ExecutionEngineException | Invalid call to method 'Naninovel.LocalResourceProvider::AddConverter'
  ```
  `AddConverter<T>` 是泛型方法,`il2cpp_class_get_method_from_name` 返回**泛型方法定义**(is_generic=1),`runtime_invoke` 无法调用裸泛型 DEF。

### 2. Windows vs macOS 差异确认
- 两版 global-metadata **同版本 31**(Unity 6 时代 IL2CPP),各表 count 几乎一致(stringCount 2189760 vs 2192284)。同一 Unity 版本的同一游戏,不同平台构建。
- Windows dump.cs 显示 LRP.ctor 有 RVA(0x536DE0);macOS 探针确认 ctor 也编译了(methodPointer 非空,反汇编是真实方法体)。
- **两版差异不在"是否编译",而在调用时序**:旧代码在 thread_attach 之前调 AddConverter → 归因错位。macOS 上没有"缺 AOT 代码"这回事。

### 3. FSG 破墙: inflated 泛型方法可以经 runtime_invoke 调用 ⭐⭐
决定性实验: 从**实例化后的泛型类**(如 `Dictionary<string, LoadedResource>`)取方法,`cgm` 返回 `is_generic=0, is_inflated=1`,`runtime_invoke` **正常**。
- **规则**: 定义类本身是泛型实例化 → 取到的 inflated 方法可调;定义类非泛型的泛型方法(如 `AddConverter`、`ResourceProvider` 上的泛型方法)→ 只有泛型 DEF → 不可调。
- 因此**绕开 AddConverter**: 直接填充 converters 字典 `Dictionary<Type, List<IConverter>>`:
  1. LRP 构造后 +0x58 是新鲜空字典,从它的 genericInst 挖 `List<IConverter>` 类:
     `il2cpp_class_get_type` → `Il2CppType.data.generic_class`(+0x0) → `context.class_inst`(+0x8) → `type_argv`(+0x8) → `[1]` → `il2cpp_class_from_type`
  2. `object_new` + inflated `List.ctor(0)` + inflated `List.Add(NaniToScriptAssetConverter)`
  3. `il2cpp_type_get_object(il2cpp_class_get_type(Script))` 拿托管 `typeof(Script)` 作 key
  4. inflated `Dictionary.Add(typeObj, list)`

### 4. 布局修正(血泪)
- `Il2CppType.type` 字节在 **+0x0C**(attrs 是 u32),不是 +0x0A。
- IL2CPP 数组: bounds **+0x10**(SZARRAY 为 NULL)、max_length **+0x18**、数据 **+0x20**。
- `AudioClip` 在 `UnityEngine.AudioModule`,不在 CoreModule;TextAsset 在 CoreModule。

### 5. 直接裸调 `ScriptLoader.Load` 会崩溃
探针里直接 `runtime_invoke` ScriptLoader.Load 导致游戏 **SIGSEGV @0x8**(主线程 null 解引用)。原因是缺游戏侧执行上下文。
**解决: 让游戏自己的 @goto 驱动**(菜单 choice → GotoModified → ScriptLoader.Load),不做裸调。这也是 v3 菜单缓存路径一直以来的做法。

## 二、provider 管线实现(v3 已接入,镜像 Windows AddModLoader)

为每个 mod(遍历 modList)注入 4 个 provider:

| Provider | 目标 | ProvisionSource | Converter |
|----------|------|----------------|-----------|
| 剧本 | `ScriptLoader.ProvisionSources` | `<key>/Scripts` | NaniToScriptAssetConverter (.nani) |
| 本地化 | `TextManager.textLoader.ProvisionSources` | `<key>/Text` | TxtToTextAssetConverter (.txt) |
| 声音 | `AudioManagerExtended.voiceLoader` (+0x78) | `<key>/Voice` | WavToAudioClipConverter (.wav) |
| 音频 | `AudioManagerExtended.audioLoader` (+0x70) | `<key>/Audio` | WavToAudioClipConverter (.wav) |

- LRP root = `MOD_ROOT`(绝对路径,macOS 上文件 I/O 正常,游戏自己的 LRP 就在读 Application Support)。
- 全部在 `TitleUi.Activate` onLeave 里同步执行(主线程,ScriptManager 已就绪)。
- 已证可用的新函数: `getGenericArgClass` / `populateConvertersDict(lrp, convName, targetClsFn, tag)` / `insertProvisionSource` / `addModLoader` / `addTextLoader` / `addAudioProviders`。
